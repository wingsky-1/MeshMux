# Web 信息架构与交互契约

移动优先，一套 Web 适配手机和 PC。一级导航固定为：

1. 概览：Hub/Line/Out 数量、健康、Mesh 设备、待处理任务。
2. 代理节点：Hub 的可选 Line、已纳管 Line、可选 Out；展示名、端口、纳管、停用和状态。
3. 订阅用户：订阅、线路选择、Token、发布历史、客户端链接。
4. Mesh 设备：单 VPN / Mesh-only / 子网路由三种用途；不按 iOS/Android 拆开用户身份。
5. 路由策略：客户端与服务端策略、国内/海外、AI Out 可选、例外、DNS、模拟器。
6. 任务与升级：operation_id、每节点进度、回退、失败重试、版本统一。
7. 日志与诊断：受限、脱敏的错误详情、外部探测证据。
8. 系统设置：管理员、认证安全、Fail2ban、软件基线、备份。

## 新增 Mesh 设备

输入：名称、用途（代理+Mesh / Mesh-only / 子网路由）、客户端平台（仅影响提示/配置）、可选关联订阅用户、可选通告网段。输出：单次有效配对凭据与安装/导入说明。注册后 Key 从持续发布的设备配置删除；一台设备删除不影响其他订阅和 NAS。

## 代理节点与 Out

Out 标记为 optional，不存在时 Web 和订阅均不报缺省错误。修改展示名只修改标签并原子重发订阅，不修改不可变 node ID、sing-box UUID、Headscale ID 或 SSH 身份。选择新增 Out 时先配置受限线路来源和出站规则，再在完整健康验证后允许发布。

## 路由策略视图

客户端层：家庭 Wi-Fi SSID / Tailnet / 中国地区 / 国际目标 / DNS；服务端层：默认直出、AI 指定 Out、规则匹配和异常兜底。模拟器输出“命中规则→第一跳→最终出口→DNS 选择”。

## 明确交互安全性

删除/重置/Token 轮换需要二次确认并展示影响对象；网页不会用操作结果静默遮盖 partial。首次登录不要求 Cloudflare Zero Trust。默认不将订阅 Token 存入浏览器持久化 storage。视觉草图审核通过后再实施业务按钮，禁止留下点击无动作的控件。
