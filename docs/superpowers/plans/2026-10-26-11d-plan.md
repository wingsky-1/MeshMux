> 本稿是 2026-10-26 r1 计划的重写：Task 1/3/4 按 owner D1（flat→per-op）与 D3（删镜像表、schema 保持 10）重做为 **T1r / T3r / T4r**；T5–T7 按 D2（root 侧恢复 + watchdog）与三轮 oracle carries 更新。原 Task 2（`internal/buildinfo` + 只读身份回读）已作为 PR #122 合入 main，不再列入任务。

**Goal:** 让 Hub 自己能升级：预升级 per-op DB 备份（`keep=2` confirmed-only）→ root 预置目标 manifest → 已校验 staged 包 → 协调换 Hub 二进制与 co-located Line 四处 pin → 重启 → 启动身份回读确认；任何失败都能由 root 在无浏览器、无 Web 存活的前提下恢复（restore 唯一路径）。

**Architecture:** 记录层 `internal/backup` 收敛为**纯 per-op**（唯一编码器、无 layout 参数、无 flat 恢复机制）；`<data-dir>/database-backup/<op32hex>/{record.json,payload}` 是唯一恢复源，`<data-dir>/database-backup/record.json` 只是 per-op 提交后按字节复制的**旧二进制存在性指针**，11d 从不读取。op journal（`<data-dir>/hub-upgrade/ops/<op>.json`）是状态唯一权威：**不建 DB 镜像表、不 bump schema（`user_version` 保持 10）**。版本身份唯一来源是已合入的 `internal/buildinfo`；执行面是 root 属主静态 oneshot + path unit（Web 只写 `/run` 请求文件，无特权调用）；`confirmed` 只由 running `version+digest` 判定；恢复走旧包的 `__internal-hub-restore` + 新 data-dir + drop-in 翻 `--data-dir`，root 可直接在控制台按冻结 argv 调用。

**Tech Stack:** Go 1.27.2, stdlib; `modernc.org/sqlite`（仅 Web 侧 VACUUM/`integrity_check`，与 root 侧恢复前只读连接）；`node.CommandRunner` 固定 argv；systemd 静态 oneshot + `.path` + tmpfiles + Web 单元 watchdog；既有 `install.ReadState` / `nodeManagedFiles` 编码语义。

**Spec:** `docs/superpowers/specs/2026-10-26-11d-hub-self-upgrade-design.md`（分支 `feat/11d-design`，HEAD `7a4cc37` = **r6**：已含 D3——删镜像表、`user_version` 保持 10、journal 唯一权威）。执行者必须同时读 spec 与本文；两者冲突时以本文 §0 的 ledger 决定与“spec 缺口”为准。spec 是语义权威，本文只做任务切分与文件/接口裁定。

**基线：** `main @ 8660eb5`（PR #121 = T1 扁平记录包，PR #122 = T2 buildinfo/身份回读，均已合入）。旧 PR #123（flat Task 3）按 D1 关闭不合并；分支 `feat/11d-1-backup-record`、`feat/11d-3-hub-backup`、`feat/11d-4-dispatch` 只作移植参考，不再作为交付分支。

## Review Focus

1. **per-op GC 边界**：Hub 只保留 `keep=2` 个 **confirmed** 代；`staged`/`failed` 与最新两代 confirmed 永不入选；Hub 的清理入口拒绝 `keep<2`（`internal/backup.GC` 保持参数化，Node 的 `keep=1` 不变）；GC 与指针刷新解耦，刷新失败只记 `HUB_BACKUP_POINTER_STALE`，绝不跳过 GC。测试：`TestGCKeepTwoConfirmed`、`TestGCNeverCollectsNewestOrStaged`（T1r）、`TestHubCleanupRejectsKeepBelowTwo`（T3r）、`TestConfirmCollectsConfirmedBeyondTwo`、`TestConfirmPointerFailureStillCollects`（T5）。
2. **跨 uid 属主**：root dispatcher 以 `expectedOwner=meshmux` 读 0600 记录/载荷；Web 不能读 root ledger；result 在 Web data-dir 之外；root 不得以“反正能读”绕过属主检查。测试：`TestExpectedOwnerEnforced` 的 per-op 语义（T1r）、`TestDispatchReadsMeshmuxOwnedRecord`（T4r）、`TestResultDirRejectsWebWrites`（T4r）。
3. **TOCTOU staged 换字节**：按 fd 校验后不能按路径 exec；必须复制到 root-only `exec-<op>` 再 exec。测试：`TestDispatchExecsVerifiedCopy`（T4r，保留旧分支实现）。
4. **claim 文件崩溃窗口**：claim 必须在 **rename 换二进制之前** 落盘（旧稿“swap 后再写”留一个 syscall 级裸窗口，正是 R1 指出的失效点）；boot 对账按 claim phase + running digest 区分“未换成功 / 换成功但未重钉 / 已重钉未清理”三种；`swapping` + running==target ⇒ 立刻 `HUB_SHARED_BINARY_REPIN_INCOMPLETE`，restore 不等 30min。测试：`TestClaimWrittenBeforeSwap`、`TestReconcileClaimSwappingNewBinary`、`TestReconcileClaimOldBinaryInert`、`TestReconcileRepinnedClaimInert`（T6/T5）。
5. **busy 判据与位清除**：单飞只看 journal 非终态；`irreversible_approved` 不再参与 busy，Confirm 成功后必须清除，否则一次不可逆升级永久锁死后续备份。测试：`TestBackupSingleFlight`（位为 true 不阻塞）、`TestApproveConfirmRebackup`（T3r）、`TestApproveAndConfirmDoNotTakeProduceLock`（T5）。

## 与 spec 的既有裁定（执行者不得自行发明）

1. **`/var/lib/meshmux-installer` 的 0700 与可读性冲突**：沿用 r1 裁定，改 `0711`（可穿越、不可列举）；`hub-upgrade/`、`upgrade/` 各 0755，`results/` 0750 `root:meshmux`；两个 ledger 仍 0600 root，`local-line/` 仍 0700。T4r 用 R-SURFACE 测试钉住。
2. **Web 单元没有请求目录写权**：沿用 r1 裁定，`meshmux-web.service` 渲染追加 `ReadWritePaths=/run/meshmux-hub/requests`（T4r）。
3. **restore 没有 `restoring` journal 状态**：spec §5.2 回执写 `status=restoring` 但 §5.5 状态机无此状态。裁定：restore 要求 journal `∈ {failed, partial, verifying}`、不存在任何请求文件、journal 不是 `queued|applying|restarting`，否则 `HUB_HANDOFF_BUSY`/`HUB_UPGRADE_BUSY` 零写；restore 期间事实由请求文件 + result 表达，journal 不新增状态（T7）。
4. **claim 写序**：oracle 原文“after swap”按**换字节前落盘**实现（phase=`swapping` 覆盖整段 swap→re-pin），理由见 Review Focus 4；这不是新增授权面，claim 只是一份带旧 pin 的崩溃锚，root 写、Web 只读、删除由 root 完成。
5. **GC keep 是调用点策略**：`internal/backup.GC(root, keep)` 保持参数化；Hub 入口只允许 `2`/`max(2, x)`，Node 走 `KeepConfirmed=1`。不得把 `2` 写进 `internal/backup` 的默认值。
6. **manifest 门在 producer 锁之前**：`WriteOp(backing_up)` 的 `validateOp` 要求 `manifest_sha256`/`package_sha256` 已是 64 hex（`journal.go`），所以 spec §5.2 “先写 `backing_up`、锁外再解析 manifest”不可实现。裁定：**root manifest 读取与目标门先在锁外完成**（root 属主只读文件，不慢在锁上），随后才进锁做 `Busy → generation → WriteOp(backing_up)`；锁内仍必须重读 journal，不得复用进锁前的 Busy 结论。

## spec 缺口（最多 3 条；执行时以本文裁定为准）

1. **busy 判据（R2）**：r6 §5.2 仍把“最新可读记录的 `irreversible_approved=true`”列为 `HUB_UPGRADE_BUSY` 条件。本文按 oracle R2 改为**仅 journal 非终态**，并由 Confirm 清除该位；否则一次不可逆升级会让后续备份永久 BUSY。
2. **manifest 门与 producer 锁的顺序**：r6 §5.2 写“先写 `backing_up`、随后锁外解析 manifest”，但 journal `validateOp` 要求 `manifest_sha256`/`package_sha256` 在 `WriteOp` 时已是 64 hex——按字面实现会 fail-closed。本文裁定 manifest 门在锁外**先**做、再进锁查后写（裁定 6）。
3. **D2 / oracle 新增未入 spec**：`backing_up`/`backed_up`/`restarting` 孤儿超时、root 可控制台恢复、Web `WatchdogSec`/`StartLimitBurst` + 启动守卫、claim 文件与 `HUB_SHARED_BINARY_REPIN_INCOMPLETE`、restore LOSSY 标注均不在 r6 文本；落地后应补入 §5.5/§5.6/§5.7/§5.9。
